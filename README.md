# 📸 Photo Battle Bot

Telegram-бот для фотобатлов. Участники присылают фотографии в бота. Бот проверяет их, ставит в очередь и автоматически публикует в Telegram-канал с кнопкой голосования «🔥 Поддержать». Администраторы управляют всем процессом прямо в Telegram.

**Стек:** Node.js 22 · TypeScript · Telegraf 4.16 · PostgreSQL 16 + Prisma 7 · Redis + BullMQ 6 · sharp · zod · pino · Vitest · Docker.

## Возможности

### Для участников
| Функция | Описание |
|---|---|
| 📸 Отправка фото | Как сжатое фото или как файл JPG/PNG/WEBP. Проверяются формат, размер, разрешение и целостность (полное декодирование). Есть предпросмотр, подтверждение и отмена. |
| ✅ Согласие | Перед первой отправкой пользователь явно соглашается на публикацию в публичном канале. Согласие сохраняется в БД. |
| 🏆 Мои фотографии | Список со статусами: ожидает подтверждения, на модерации, в очереди, опубликована, отклонена, удалена. Карточка фото со ссылкой на публикацию. |
| 🗑 Удаление | Любое своё фото удаляется вместе с постом в канале. Команда `/deletedata` удаляет все фото пользователя. |
| 📊 Моя статистика | Дата регистрации, отправлено, опубликовано, в очереди, полученные голоса, место в рейтинге. |
| 🥇 Рейтинг | Топ-10 участников по голосам и лидеры текущего батла. |
| ⚔️ Батлы | Информация о текущем батле: тема, сроки, число участников. |
| 🔥 Голосование | Кнопка под постом в канале: один голос на фото, повторное нажатие отменяет голос, за себя голосовать нельзя. Счётчик на кнопке обновляется автоматически. |

### Для администраторов (`/admin` или кнопка «🛠 Админ-панель»)
- 📊 Статистика: пользователи (всего, новые за сутки, заблокированные), фото (получено, опубликовано, в очереди, на модерации, отклонено, с ошибкой, удалено), публикации за сутки, голоса.
- 👥 Пользователи: список, карточка, блокировка и разблокировка, фото пользователя.
- 📸 Все фотографии: фильтры по статусу, карточка с действиями.
- ⏳ Очередь публикаций в порядке выхода, включая фото, которые публикуются сейчас, и фото с ошибкой.
- 🛡 Модерация: одобрить или отклонить с выбором причины. Автор получает уведомление.
- 🚀 Ручная публикация (по кнопке или по ID `#0012`) — работает даже при паузе.
- 🗑 Удаление фото, в том числе из очереди и из канала.
- 🚫 / 🔓 Блокировка по Telegram ID, `@username` или ID фото. Неопубликованные фото заблокированного пользователя снимаются с очереди.
- ⏸ / ▶️ Остановка и возобновление автопубликаций.
- ⚙️ Настройки: интервал (вручную, 5, 15, 30 мин, 1, 3, 6 ч), модерация, голосование, лимиты (в сутки, в очереди, на батл), приём только во время батла, еженедельные батлы.
- 📢 Объявления: любое сообщение (текст, фото, видео с форматированием) рассылается всем с предпросмотром. Скорость ограничена с учётом лимитов Telegram, а прерванная рассылка продолжается после перезапуска.
- ⚔️ Батлы: создание (название, тема, длительность приёма и голосования) с анонсом в канале. Можно досрочно закрыть приём, подвести итоги или отменить батл. Победитель выбирается автоматически.

### Надёжность и безопасность
- Права администратора проверяются на сервере по таблице `Admin`, которая синхронизируется с `ADMIN_IDS` при каждом запуске. Каждая попытка доступа без прав записывается в журнал.
- Повторные нажатия обрабатываются идемпотентно: переходы статусов атомарны (`DRAFT → QUEUED` выполняется ровно один раз), а Redis-блокировки защищают кнопки и загрузки.
- Дубликаты отсекаются по SHA-256 содержимого и `file_unique_id`: одну и ту же фотографию нельзя отправить повторно (в том числе другим пользователем).
- Защита от спама: лимит действий в минуту на пользователя, лимиты фото в сутки, в очереди и на батл, обработка только первого фото из альбома.
- Неподтверждённые фото не публикуются никогда: в очередь попадает только фото после подтверждения автором (и одобрения модератором, если модерация включена).
- Повторные попытки при временных ошибках Telegram: экспоненциальная задержка, учёт `retry_after` при 429, ограниченное число попыток. Постоянные ошибки (нет прав, канал не найден) сразу помечают фото как «ошибка публикации» и уведомляют администраторов.
- Двойная публикация исключена: `Publication.photoId` уникален, а после успешной отправки результат записывается без повторной отправки.
- Журнал действий (`ActivityLog`) и структурированные логи (pino). Токен бота маскируется в логах и сообщениях об ошибках.
- У изображений, присланных файлом, удаляются EXIF-метаданные, в том числе GPS.

## Как это работает

```
Пользователь ──► Бот (Telegraf) ──► PostgreSQL (Prisma)
                     │                  ▲
                     ▼                  │
                 Redis/BullMQ ──► Воркеры ──► Telegram-канал
```

1. Пользователь присылает фото. Бот скачивает файл, проверяет его через `sharp`, создаёт запись `Photo` со статусом `DRAFT` и показывает предпросмотр с кнопками.
2. После подтверждения статус меняется на `QUEUED` (или `PENDING_MODERATION`) и создаётся запись в `PublicationQueue`.
3. Каждую минуту воркер выполняет *тик*. Если публикации не на паузе и с прошлой публикации прошло не меньше интервала, он забирает первое фото из очереди (FIFO) и ставит задачу публикации.
4. Задача отправляет фото в канал. При временной ошибке BullMQ повторяет попытку с задержкой. Пока фото повторяется, следующее не берётся — порядок сохраняется.
5. После успеха создаётся `Publication` с `message_id`, автор получает ссылку на пост.
6. Голоса копятся в `Vote`. Обновления счётчика на кнопке объединяются (не чаще раза в 2 секунды на пост) и ограничены по частоте.

**PostgreSQL** — источник истины для порядка и статусов. **BullMQ** отвечает за расписание, повторные попытки и фоновые задачи: публикации, обновление счётчиков, рассылки, переходы этапов батлов, очистку просроченных черновиков, еженедельные батлы.

## 1. Создание бота через BotFather и получение токена

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите отображаемое имя (например, `Photo Battle`) и username, который заканчивается на `bot` (например, `my_photobattle_bot`).
3. BotFather пришлёт **токен** вида `1234567890:AAH...`. Это `BOT_TOKEN`.
   > ⚠️ Токен — это пароль от бота. Не публикуйте его и не коммитьте в Git. Если он утёк, выполните `/revoke` в BotFather и получите новый.
4. Рекомендуемые настройки в BotFather:
   - `/setdescription` и `/setabouttext` — описание бота;
   - `/setuserpic` — аватар;
   - `/setjoingroups` → **Disable**: бот работает только в личных сообщениях и в канале.

## 2. Создание Telegram-канала

1. В Telegram: **Новый канал** → название → тип **публичный** (с @username) или **частный**.
2. В публичном канале ссылки на посты выглядят как `t.me/username/123`. Для частного канала бот строит ссылки вида `t.me/c/...`, которые открываются только у подписчиков.

## 3. Добавление бота в канал администратором

1. Откройте канал → **Управление каналом** → **Администраторы** → **Добавить администратора**.
2. Найдите бота по username и выдайте права:
   - ✅ **Публикация сообщений** (Post messages) — обязательно;
   - ✅ **Редактирование чужих сообщений** (Edit messages of others) — для счётчика голосов на кнопке;
   - ✅ **Удаление чужих сообщений** (Delete messages of others) — для удаления фото по запросу.
3. При запуске бот сам проверит доступ к каналу и права. Если чего-то не хватает, в логе появится понятное предупреждение, а без прав администратора бот не запустится.

## 4. Как узнать ID канала

- **Публичный канал:** можно указать `CHANNEL_ID=@username_канала`. При запуске бот сам определит числовой ID.
- **Частный канал:** нужен числовой ID вида `-100XXXXXXXXXX`. Способы:
  1. Перешлите любой пост из канала боту [@userinfobot](https://t.me/userinfobot) или [@getidsbot](https://t.me/getidsbot) — он покажет ID вида `-100…`.
  2. Или откройте канал в [web.telegram.org](https://web.telegram.org/a/): в адресной строке будет `#-100XXXXXXXXXX`.

**Свой Telegram ID** (для `ADMIN_IDS`) можно узнать у [@userinfobot](https://t.me/userinfobot): отправьте ему любое сообщение.

| `BOT_MODE` | | `polling` | `polling` или `webhook` |

| `WEBHOOK_PATH` | | `/telegram/webhook` | Путь webhook |
| `WEBHOOK_SECRET` | в webhook | — | Секрет (16–256 символов `A-Za-z0-9_-`), Telegram передаёт его в заголовке |
| `PORT` | | `8080` | Порт HTTP: `/health` и webhook |
| `APP_ROLE` | | `all` | `all` — бот и воркеры в одном процессе; `bot` или `worker` — раздельно |
| `TIMEZONE` | | `Europe/Kyiv` | Часовой пояс дат и расписания еженедельных батлов |
| `MAX_PHOTO_SIZE_MB` | | `10` | Максимальный размер файла (не больше 20 — лимит Bot API) |
| `MIN_PHOTO_DIMENSION` / `MAX_PHOTO_DIMENSION` | | `320` / `10000` | Допустимое разрешение, px |

| `PUBLISH_MAX_ATTEMPTS` | | `5` | Попыток публикации при временных ошибках |
| `PUBLISH_RETRY_BASE_MS` | | `30000` | Первая задержка повтора (далее ×2, максимум 30 мин) |
| `DRAFT_TTL_HOURS` | | `24` | Через сколько часов отменяется неподтверждённый черновик |
| `BROADCAST_RATE_PER_SECOND` | | `20` | Скорость рассылки объявлений |

| `TELEGRAM_API_ROOT` | | — | Адрес self-hosted Bot API server (необязательно) |
| `LOG_LEVEL` | | `info` | `debug`, `info`, `warn`, `error` |

Настройки, которые меняются во время работы (интервал, пауза, модерация, лимиты, голосование, батлы), хранятся в БД (`BotSettings`) и редактируются в админ-панели без перезапуска.

## 6. Локальный запуск

Требования: **Node.js 22+**, **PostgreSQL 14+**, **Redis 6.2+** (или Docker).

```bash
# 1. Зависимости
npm install

# 2. PostgreSQL и Redis (если нет своих) — поднять только их из docker-compose
docker compose up -d postgres redis
#    тогда в .env:
#    DATABASE_URL=postgresql://photobattle:<POSTGRES_PASSWORD>@localhost:5432/photobattle?schema=public
#    REDIS_URL=redis://localhost:6379

# 3. Схема БД и первоначальная настройка (настройки + администраторы)
npm run db:generate
npm run db:setup          # = prisma migrate deploy + prisma db seed

# 4. Запуск в режиме разработки (перезапуск при изменениях)
npm run dev
```

Production-сборка без Docker:

```bash
npm ci
npm run build             # prisma generate + tsc → dist/
npm run start:prod        # prisma migrate deploy + node dist/index.js
```

Все скрипты:

| Скрипт | Назначение |
|---|---|
| `npm run dev` | Запуск из исходников с автоперезапуском |
| `npm run build` | Генерация Prisma Client и компиляция в `dist/` |
| `npm start` / `npm run start:prod` | Запуск собранной версии (`start:prod` сначала применяет миграции) |
| `npm run typecheck` | Проверка типов всего проекта, включая тесты |
| `npm run db:migrate` | Создать и применить новую миграцию (разработка) |
| `npm run db:deploy` | Применить миграции (production) |
| `npm run db:seed` | Создать настройки по умолчанию и администраторов из `ADMIN_IDS` |
| `npm run db:setup` | `db:deploy` + `db:seed` |
| `npm run db:studio` | Prisma Studio — просмотр БД в браузере |
| `npm test` / `test:unit` / `test:integration` | Тесты |

> Первоначальная настройка (строка `BotSettings`, синхронизация `ADMIN_IDS`) выполняется и при каждом запуске бота, поэтому seed запускать не обязательно.

## 7. Подключение PostgreSQL

Подойдёт любой PostgreSQL 14+: локальный, в Docker, Railway, Supabase, Neon, managed-БД провайдера.

```bash
# Пример для локального сервера
sudo -u postgres psql -c "CREATE USER photobattle WITH PASSWORD 'strong-password';"
sudo -u postgres psql -c "CREATE DATABASE photobattle OWNER photobattle;"
```

```env
DATABASE_URL=postgresql://photobattle:strong-password@localhost:5432/photobattle?schema=public
```

Для облачных БД обычно требуется SSL: добавьте `&sslmode=require` в конец строки.

Затем примените миграции: `npm run db:deploy` (Docker-образ делает это автоматически при старте).

Таблицы: `User`, `Photo`, `PublicationQueue`, `Publication`, `Vote`, `Battle`, `Admin`, `BotSettings`, `Broadcast`, `ActivityLog`. Схема — `prisma/schema.prisma`, миграции — `prisma/migrations/`.

## 8. Развёртывание

### Вариант A — VPS с Docker Compose (рекомендуется)

Всё в одном: бот, PostgreSQL и Redis с постоянными томами.

```bash
# на сервере (Ubuntu 22.04+), Docker уже установлен
git clone https://github.com/<you>/photo-battle-bot.git
cd photo-battle-bot
cp .env.example .env
nano .env                 # BOT_TOKEN, CHANNEL_ID, ADMIN_IDS, POSTGRES_PASSWORD
docker compose up -d --build
docker compose logs -f bot
```

`DATABASE_URL` и `REDIS_URL` для контейнера бота задаются в `docker-compose.yml` автоматически. Миграции применяются при каждом старте контейнера.

Обновление:

```bash
git pull
docker compose up -d --build
```

Резервная копия БД:

```bash
docker compose exec postgres pg_dump -U photobattle photobattle > backup-$(date +%F).sql
```

### Вариант B — VPS без Docker (systemd)

```bash
npm ci && npm run build && npm run db:deploy
```

Файл `/etc/systemd/system/photobattle.service`:

```ini
[Unit]
Description=Photo Battle Bot
After=network.target postgresql.service redis-server.service

[Service]
WorkingDirectory=/opt/photo-battle-bot
EnvironmentFile=/opt/photo-battle-bot/.env
ExecStart=/usr/bin/node dist/index.js
Restart=always
User=photobattle

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
```

```bash
sudo systemctl enable --now photobattle
```

### Вариант C — Railway

1. Загрузите проект на GitHub (см. ниже).
2. На [railway.com](https://railway.com): **New Project → Deploy from GitHub repo** → выберите репозиторий. Railway соберёт образ по `Dockerfile` (настройки в `railway.json`).
3. В проекте: **+ New → Database → PostgreSQL** и **+ New → Database → Redis**.
4. В сервисе бота откройте **Variables** и добавьте:
   - `BOT_TOKEN`, `CHANNEL_ID`, `ADMIN_IDS`;
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`;
   - `REDIS_URL` = `${{Redis.REDIS_URL}}`.
5. По желанию режим webhook: **Settings → Networking → Generate Domain**, затем `BOT_MODE=webhook`, `WEBHOOK_DOMAIN=https://<домен>.up.railway.app`, `WEBHOOK_SECRET=<openssl rand -hex 32>`. Режим polling тоже работает на Railway, домен для него не нужен.
6. Deploy. Health check — `/health`.

> ⚠️ В режиме **polling** должен работать **ровно один** экземпляр бота (`numReplicas: 1`), иначе Telegram вернёт ошибку 409. Для масштабирования используйте webhook или вынесите воркеры (`APP_ROLE=worker`, `SKIP_MIGRATIONS=true`) в отдельный сервис.

## 9. Проверка работоспособности

1. **Логи при запуске** должны содержать:
   `Authorized in Telegram` → `Channel resolved` → `Background workers started` → `Long polling started` (или `Webhook registered`).
   Если есть проблемы с правами в канале, появится предупреждение `Channel permission problems: …`.
2. **Health check:** `curl http://localhost:8080/health` → `{"status":"ok","database":true,"redis":true}`.
3. **Сценарий в Telegram:**
   1. `/start` — приветствие и меню;
   2. «📸 Отправить фотографию» → согласие → отправьте фото → «✅ Подтвердить»;
   3. фото появится в канале сразу (если с прошлой публикации прошло больше интервала) или в порядке очереди; автор получит ссылку;
   4. нажмите «🔥 Поддержать» под постом с **другого** аккаунта — счётчик обновится;
   5. администратор: `/admin` → «📊 Статистика бота».
4. **Если фото не публикуется:** проверьте в админ-панели, что публикации не на паузе и интервал не «вручную». В «⏳ Очереди» видна последняя ошибка у фото; при постоянной ошибке администраторы получают сообщение с её текстом.

### Добавление украинского языка

1. Создайте `src/i18n/locales/uk.ts`: `export const uk: Locale = { ... }`. TypeScript не даст пропустить ни одного ключа.
2. Зарегистрируйте его в `src/i18n/index.ts` (`const locales = { ru, uk }`) и добавьте `'uk'` в `DEFAULT_LANGUAGE` в `src/config/env.ts`.

Язык пользователя берётся из его профиля Telegram (`User.languageCode`). Кнопки меню распознаются на всех зарегистрированных языках.

## Эксплуатация и ограничения

- **Интервал публикаций** считается от последней публикации, точность ±1 минута (тик раз в минуту). Режим «Вручную» отключает автопубликацию.
- **Пауза** останавливает только автоматическую публикацию. Ручная публикация и уже идущие повторные попытки продолжают работать.
- **Удаление поста из канала** требует права «Удаление сообщений». Если Telegram не дал удалить пост, фото всё равно помечается удалённым, а администраторы получают ссылку для ручного удаления.
- **Размер файлов** ограничен 20 МБ — это лимит скачивания стандартного Bot API. Для больших файлов нужен self-hosted Bot API server (`TELEGRAM_API_ROOT`).
- **Голоса** можно отдавать с момента публикации. Победитель батла выбирается в момент завершения по числу голосов; при равенстве побеждает фото, опубликованное раньше. Фото, не успевшие выйти к концу батла, в выборе не участвуют.
- **Счётчик на кнопке** обновляется с задержкой около 2 секунд — так Telegram не ограничивает редактирование сообщений.
- **Polling** допускает только один экземпляр бота. Для горизонтального масштабирования используйте webhook.
- **Счётчики профиля:** «отправлено» и «опубликовано» — исторические значения. Голоса удалённых фото вычитаются из рейтинга.
